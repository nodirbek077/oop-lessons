Encapsulation

Bu maqolada Java-da Encapsulation haqida gaplashamiz.


Encapsulation - enkapsuliatsiya bu OOP ning 4ta prinsipidan bittasi. Qolgan 3tasi bular inheritance, polymorphism, va abstraction. Bularni dars davomida o'rganamiz.

Encapsulation - kapsulaga olish deb tarjima qilsak bo'ladi. Boshqa tarjimasi yo'q ekan. Bori shu. Darslar davomida encapsulation (enkapsuliatsiya) deb ishlatib ketamiz.

Yaniy Encapsulation bu class o'zgaruvchilarini va shu o'zgaruvchilarga tegishli bo'lgan metodlarni bog'lab bitta qilib ishlatish mexanizmi. Enkapsuliatsiyada class o'zgaruchilariga to'gridan to'g'ri murojaat qilinmaydi. Class o'zgaruvchilarini qiymatini olish yoki qiymatini o'zgartirish uchun shu classning maxsus getter va setter metodlarini ishlatish kerak.

Enkapsuliatsiyaning boshqa bitta tarifi bu - data hiding . Ya'ni class o'zgaruvchilarini yashirish. To'g'ridan to'g'ri foydalanishni taqiqlash.

Enkapsuliatsiyaga erishish uchun quyidagi ishlar bajariladi.

  • 1. private o'zgaruvchilar yaratiladi.
  • 2. Shu o'zgaruvchilarni qiymatini olish va o'zgartirish uchun public getter/setter metodlar yaratiladi.

Bo'ldi shu bilan enkapsuliatsiyaga erishiladi.

Enkapsuliatsiya inglizcha tarifi: Encapsulation in Java is a mechanism of wrapping the data (variables) and code acting on the data (methods) together as a single unit.

Agar siz OOP da kode yozaman desangiz enkapsuliatsiyadan to'liq foydalanishingiz kerak.


Namuna

public class Person {
    private String name;
    private String surname;
    private Integer age;


    public String getName() { return name; }

    public void setName(String name) { this.name = name; }

    public String getSurname() { return surname; }

    public void setSurname(String surname) { this.surname = surname; }

    public Integer getAge() { return age; }

    public void setAge(Integer age) { this.age = age; }
}

Namunada: Person classiga e'tibor bering. Unda 3ta o'zgruvchi bor va o'zgaruvchilarning barchasi private qilingan. Ya'ni o'zgaruvchilarni tashqaridan murojaat qilib bo'lmaydi.

Class da har bir o'zgaruvchi uchun getter / setter metodlar yozilgan.

Getter - metodi o'zgaruvchining qiymatini olish (o'qish) uchun ishlatiladi. Get - qiymatini olish/o'qish deb tarjima qilsak bo'ladi.

Setter - metodi o'zgaruvchiga qiymat berish uchun ishlatiladi. Set - o'rnatish/berish deb tarjima qilinadi.

Qo'shimch

  • setName(String name) - metodi bu setter metodi deyiladi. Set Name deyilyabdi. Ya'ni name o'zgaruvchisiga qiymat berish uchun ishlatiladi. Metodga kelgan name bu yangi qiymat.
    this.name = name deb :
    • this.name - bu shu classdagi global name o'zgaruvchisi nazarda tutilgan.
    • = name - bu metodga kelgan name o'zgaruvchisi. Ya'ni yangi qiymat.
  • getName() - metodi name o'zgaruvchisining qiymatini return qiladi. Shu sabadam getName() metodi String tipli nimadir return qiladi. Nima uchun String sababi name bizda String tipli.

Qanday ishlatish kerak.

public class Main {

    public static void main(String[] args) {
        Person person = new Person();
        person.setName("Ali"); // name o'zgaruvchisini 'Ali' qiymatini berish
        person.setSurname("Aliyev"); // surname o'zgaruvchisiga 'Aliyev' qiymatini berish
        person.setAge(22); // age qiymatiga 22 ni berish

        System.out.println(person.getName()); // name o'zgaruvchisining qiymatini olish
        System.out.println(person.getSurname()); // surname o'zgaruvchisini qiymatini olish
        System.out.println(person.getAge()); // age o'zgaruvchisini qiymatini olish/
    }
 }

Namunada Main classning main metodi orqali Person classini ishlatyapmiz.

Person class dan ob'ekt olindi va ob'ektni orqali set metodlari chaqirilib o'zgaruvchilarga qiymatlar berildi.

Undan keyin shu ob'ekt orqali get metodlari chaqirilib o'zgaruvchilarning qiymatlari konsolga chiqarildi.


Afzalliklari

Enkapsuliatsiyani bir nechta afzalliklari bor. Ular :

  • Ma'lumotni yashirish. User to'gridan to'gri o'zgaruvchilarga murojaat qila olmaydi. User class dagi malumotlar qanday saqlanishini bilmaydi.
    User biladiki set metodi orqali qiymatni berib yuborsa va get metodi orqali qiymatni oladi. Class ichida qiymatlar qanday saqlanishini bilmaydi.
    Bu huddi televizorni pultiga o'xshaydi. Ovozini baland qilish tugmasini bosamiz ovoz baland bo'ladi. Lekin tugma bosilganda televizorni ichida tranzistorlar ning qarshiliklari o'zgarishini User bilishi kerak emas.
    Userga u narsalarning qizig'i yo'q. User oddiy tugmani bossa bo'ldi.
  • Moslashuvchanlikni oshiradi. Biz classdagi o'zgaruvchilarni faqat o'qish uchun ochib qo'yishimiz mumkin. Ya'ni faqat get metodini yaratib qo'yamiz va o'zgaruvchilarning qiymatini olish mumkin halos. Bunda setter metod yaratmaymiz va o'zgaruvchilarning qiymatini o'zgartirib bo'lmaydi.
  • Nazaorat qilish uchun oson. Ya'ni o'zgaruvchining qiymati o'zgardimi yo'qmi shuni nazorat qilishimiz mumkin. Bunda o'zgaruvchining qiymati o'zgarganini setter metodi orqali bilish mumkin.

Hayotiy misollar

Endi keling yana yaxshilab yanchib tashlaydigan darajada tushunishingiz uchun bir nechta hayotiy misollar orqali buni ko'rib chiqamiz.

Encapsulation ga erishish uchun maxsus getter va setter metodlari doimiy bor bo'lishi shart emas. Bunda 3 holatga e'tibor bering:

  • Read-Write: Getter + Setter. Bu eng ko'p uchraydigan holat. Siz ma’lumotni ham ko‘ra olasiz, ham uni xohlagan paytda yangilay olasiz.
    Telefoningizdagi budilnik vaqti: Hozir 5:00 ga qo'yilganligini ko'rib turibsiz (Get) va xohlasangiz uni 4:45 ga o'zgartirishingiz mumkin (Set)
    Xonadagi konditsioner harorati: Hozir necha gradusligini displeyda ko'rasiz (Get) va pult orqali uni o'zgartira olasiz (Set).
  • Write-Only: Only Setter. Siz ma’lumotni tizimga kiritasiz, lekin tizim sizga kiritilgan ma’lumotni qayta ko‘rsatmaydi (xavfsizlik yoki mantiq yuzasidan).
    Bankomatdagi PIN-kod: Siz PIN-kodni o'zgartirayotganingizda yangi kodni kiritasiz (Set), lekin ekran uni yulduzchalar qilib ko'rsatadi yoki umuman ko'rsatmaydi. Siz uni "o'qiy" olmaysiz.
    Xayriya qutisi: Masjid yoki biror joydagi ehson qutisiga pul tashlaysiz (Set). Ichida qancha pul borligini yoki siz tashlagan pul qayerda turganini ko'ra olmaysiz (Get yo'q).
  • Read-Only: Only Getter. Bu shunday holatki, siz ma’lumotni ko‘ra olasiz, lekin uni aslo o‘zgartira olmaysiz. Tizim sizga faqat "o‘qish" huquqini beradi.
    Tug'ilgan kuningiz: Siz pasportingizda tug'ilgan kuningizni ko'rishingiz mumkin, lekin uni o'zgartirish (Set qilish) imkoniyati sizda yo'q.
    Chekdagi summa: Do'kondan xarid qilganingizda beriladigan chekdagi summa. Siz uni ko'rasiz, lekin chek bosilib chiqqandan keyin summani o'zgartira olmaysiz.
